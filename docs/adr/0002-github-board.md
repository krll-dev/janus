# 0002. Kanban vs Sprints

## Status

Akzeptiert

## Kontext

Das Projekt wird von einer Person bearbeitet. Um einen Abbruch des Projkets zu vermeiden, weil die letzte Bearbeitung des Projekts längere Zeit her ist, soll ein strukturierter Ablauf eingeführt werden.

## Entscheidungstreiber

- Solo-Projekt
- Projekt-Struktur
- Nachvollziehbarkeit

## Betrachtete Optionen

- Sprint eintulung
- Kanban

## Entscheidung

Kanban-Board auf GitHub.

## Konsequenzen

### Positiv

- Keine Sprints oder ähnliches nötig. Aufgabe wird einfach genommen und bearbeitet, wenn privat Ziet dafür ist.

### Negativ / Trade-offs

- Keine bekannt, da subjekte Entscheidung.
