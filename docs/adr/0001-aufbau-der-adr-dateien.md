# 0001. Aufbau der *Archtectural Decision Record (ADR)* Dateien

## Status

Akzeptiert

## Kontext

Entscheidungen des Projekts sollten Dokumentiert werden. Sowohl für mich als Programmierer, als auch für den Einsatz der Agenten sollten größere Entscheidungen dokumentiert werden.

## Entscheidungstreiber

- Solo-Projekt
- Projekt-Struktur
- Nachvollziehbarkeit

## Betrachtete Optionen

Da eine umfassende Recherche für ein Template das Zeitlich den Projektverlauf behindern würde, wurden hierbei keine Optionen betrachtet.

## Entscheidung

Template, welches von Claude vorgeschlagen wurde:

```markdown
# 000X. Name

## Status
Akzeptiert

## Kontext
[Welches Problem/welche Entscheidung stand an? 2–4 Sätze. Fakten, keine Wertung.]

## Entscheidungstreiber
- [z. B. Solo-Projekt, begrenztes Zeitbudget]
- [z. B. Interview-Signalwert]

## Betrachtete Optionen
- Option A
- Option B
- Option C

## Entscheidung
Gewählt: **Option X**, weil [Begründung].

## Konsequenzen
### Positiv
- ...
### Negativ / Trade-offs
- ...
```

## Konsequenzen

### Positiv

- Erster subjektiver Eindruch des Templates: Minimal, aber dennoch aussagekräftige Struktur

### Negativ / Trade-offs

- Mir ist jetzt schon bewusst, dass es kein richtig oder falsch gibt, weshalb die Dokumentation durch das minimalstische Format ggf. wenig aussagekräftig sein wird.
